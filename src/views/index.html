Estratégia de Acesso ao Banco de Dados (ORM + Padrão DAO)

Alinhamento entre o Diagrama de Classes, o Diagrama de Componentes (MVC) e a Camada de Persistência Relacional

1. Mapeamento Objeto-Relacional (ORM)

Utiliza a estratégia Joined Table Inheritance (Herança por Tabelas Juntadas): a tabela base usuarios armazena credenciais e metadados comuns (id, nome, email, hash_senha, tipo_usuario), enquanto as tabelas especializadas alunos, professores e empresas_parceiras possuem chave primária/estrangeira usuario_id vinculada com ON DELETE CASCADE.

2. Padrão DAO (Data Access Object)

Implementa a interface genérica GenericDAO[T] (src/dao/base_dao.py) concretizada por AlunoDAO, EmpresaParceiraDAO e CatalogoDAO. Todo acesso SQL fica encapsulado nos DAOs sob transações atômicas (Unit of Work em DatabaseManager.transaction()).

3. Comunicação Front-end ↔ Back-end (REST MVC)

A camada View (HTML5/CSS3/JS Fetch API) envia requisições HTTP JSON (GET, POST, PUT, DELETE) para os endpoints /api/alunos e /api/empresas, processados por AlunoController e EmpresaParceiraController.
